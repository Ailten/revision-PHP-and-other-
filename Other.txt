
principe SOLID:
S : Single responsability  // a class should dos only one thing (like class mail, mailSender).
O : Open - close  // open to extantion, close to  update (make sub function for distinct action, not one big function who can be use in single situation).
L : Liskov subtstitution  // do not make function with raise error in a parent to be overide nextly (in this case make a second class between : bird, birdCanFly, pinguin).
I : Interface segregation  // an interface should implément only one thing (make many interface, for all little implément, to make it more flexible for other class).
D : Dependency Inversion  // don't use static method, send the static class in param method (like this it can be more flexible if we replace the static class breader in project).

Binary Search  // for search in an array stored, cut in hald, check the value midle, and continue recursively on the half you need, until find the value search.
Back tracking algorithme  // search a result, and allow to roll-back on the process, to re-search in another branch possibility (like resolving sudoku).
Dynamic programming  // subdivide functions in sub-function smaller (to make more easily used from other cases).

--> O(log(N))  // a logarythme complexity (can be eval, just calculated), browse less than length arr, and non-lineary.
example : get an element in a sorted list, by divide length by two.
def is_in_arr_ordered(arr: list[int], val_search: int):
    index = len(arr) // 2
    lenght_sub_array = len(arr)
    while lenght_sub_array < 1:
        val = arr[index]
        if val == val_search:
            return True
        lenght_sub_array //= 2
        if val < val_search:
            index += lenght_sub_array
        else:
            index -= lenght_sub_array
    return False

    - Abstraction : 
        make class generic should be Generic (not implemented specific things who don't match their generic definition).
        attributs (who don't need to be use outer the class should be not visible (private)).
        to clear the readability and usage, in a project.

        to make less redondance code, use eritage (if two class have the same function / attribute, use class parent or Interface).
    - Encapsulation :
        structurate class by logics (what their defined for).
        and make class do one thing (not many / everyting).
    - polymorphysme :
        allow a class to interact in many distinct result in distinct context.
        polymorphysme AD-OC :
            overload : 2 function can have the same name, but distinct parameters, to make distinct result.
            operator surcharge : allow to re-defined how a class should react when you use basic operator (+, -, *, /, ...).
        polymorphysme universal :
            parametrique : allow to use generic Type in a class / function, to make the same function usable on many type.
            inclusion : allow to stock an instance A in a variable of type B, if B is child of A. (allow to treat collection of generic type).
